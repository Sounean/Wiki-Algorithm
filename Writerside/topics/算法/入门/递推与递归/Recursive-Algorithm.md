# 递归算法

## 一、什么是递归

递归:函数的自我调用;


数列递归:如果一个数列的项与项之间存在关联性，那么可以使用递归实现；

原理:如果个函数可以求A(m)，那么该函数就可以求A(n-1)，就形成了递归调用;

<warning>注意:一般起始项是不需要求解的，是已知条件</warning>

递归求解问题的过程:<br/>
&emsp; 第一步:找出规律;<br/>
&emsp; 第二步:函数调用自己求解前面的项;<br/>
&emsp; 第三步:交代起始项，让递归能够停止

用递归去解题时的特点:
(1)递归就是在过程或函数里调用自身;<br/>
(2)在使用递归策略时，`必须有一个明确的递归结束条件`，称为递归出口;<br/>
(3)递归算法解题通常显得很简洁,但递归算法解题的运行效率较低。所以一般不提倡用递归算法设计程序。
(4)在递归调用的过程当中系统为每一层的返回点、局部量等开辟了栈来存储。递归次数过多容易造成栈溢出等。
由于递归的求解效率较低，且比较消耗内存，因此如果递归能够转化为循环，尽量用循 环!

## 二、递归案例

例子:定义函数，递归求解等差数列1 4 7 10 13……第n项的值

首先我们可知递归规律为:A(n) = A(n-1) + 3
```C++
#include <bits/stdc++.h>
using namespace std;

int fun(int n){
    if(n == 1){
        return 1;
    } else {
        return fun(n-1)+3;
    }
}

int main() {
    for(int i = 1;i <= 10;i++){
        cout << fun(i) << endl;
    }
    return 0;
}
```


## 三、递推和递归的区别
### 核心区别对比
| **特性**       | **递推（迭代）**                          | **递归**                              |
|----------------|-----------------------------------------|--------------------------------------|
| **方向**       | 自底向上（从初始条件逐步推导结果） | 自顶向下（从目标分解到最小子问题） |
| **实现方式**   | 循环结构（如 `for`/`while`）     | 函数调用自身                 |
| **空间效率**   | 高（仅需常量级内存，如变量存储）  | 低（需维护调用栈，可能栈溢出）  |
| **性能**       | 高效（无重复计算）              | 可能低效（未优化时重复计算子问题） |
| **代码可读性** | 逻辑直接但可能冗长                 | 简洁优雅（贴近数学归纳法）     |

<warning>不系统学习这两章节，单看这张表是绝对看不懂的。但如果能看懂这张表其实也说明了两个知识点掌握了。</warning>

以下依旧以斐波那契数列题目为例子！看下他们的区别

先列出表达式:表达式：F[n]=F[n-1]+F[n-2] (n>=2,F[0]=1,F[1]=1)

递推实现（高效无重复）:
```C++
int fib_iterative(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b;  // 逐步推导下一项
        a = b;
        b = c;
    }
    return b;
}
```
特点：从 F(0)=0、F(1)=1 开始，正向推导后续项，无函数调用开销

思想：顺着已知的结果，不断地将未知的变已知，直至求出结果。  即从边界条件出发，一步步计算出具体问题。

递归实现（简洁但低效）:
```C++
int fib_recursive(int n) {
    if (n <= 1) return n;  // 终止条件（递归基）
    return fib_recursive(n-1) + fib_recursive(n-2);  // 自我调用
}
```
思想：逆着结果出发，从最终那个未知的触发，让他从未知推到已知，再由return回归回到自身，一步步求出结果。 即从具体问题出发，一步步简化到边界条件。

此处，很多网上的文献都说“递归”方法屏蔽了“计算流程”，其实有个疑惑，以上述递归代码为例，“fib_recursive(n-1) + fib_recursive(n-2)”不就是计算过程吗？<br/>
答：“屏蔽计算流程”本质在于其底层执行机制对程序员是隐式的，而代码中的推导式（如递推公式）仅描述数学关系而非实际计算步骤。具体分析如下：1.递归的“状态隐藏”:
中间结果，比如以斐波那契数列为例子，F(4),F(3)的结果我们是无法直接观测到的;而递推的实现中，"状态可见":"int c=a+b;a=b.."中间状态是显示存储到c变量中的,且变量更新也可见.

问题：单单以计算 F(5)为例，他这步就需要 需重复计算 F(3) 两次，指数级时间复杂度（O(2ⁿ)）。(时间复杂度较高当然也有解决方案，以空间换时间的方案。)

### 适用场景对比
| **场景**               | **推荐方法** | **原因**                                                                 |
|------------------------|-------------|--------------------------------------------------------------------------|
| 斐波那契数列           | 递推        | 避免递归的重复计算，效率提升显著                                 |
| 二叉树遍历（如DFS）    | 递归        | 代码简洁，天然符合树的分支特性                                  |
| 动态规划（如背包问题） | 递推        | 可显式维护状态表，优化空间复杂度                                |
| 分治算法（如归并排序） | 递归        | 问题分解直观，逻辑清晰                                          |

不用太担心到底用哪个，哪种能写出来用哪个即可。

而有一个问题是学完后可能会疑惑的，为什么递归，他可读性比递推差、重复计算又造成时间复杂度高、调试还不如递归简单，还必须要发展这个技能点？

因为1.递归是处理树形/图状结构的天然工具：<br/>
递归是遍历树（二叉树、文件系统）、图（DFS）等分层数据的自然选择。其“自顶向下”的分治逻辑与树的分支结构完美契合，代码简洁性远高于递推 。例如：
二叉树遍历：递归代码仅需 3-5 行，而迭代需手动维护栈，代码量增加 3 倍 。
嵌套结构解析：处理 JSON/XML 嵌套数据时，递归可直接映射数据结构，而递推需复杂状态机.

2.递归完美使用了分治算法的核心实现方式:

快速排序、归并排序、汉诺塔等问题中，递归能清晰表达“分解-解决-合并”的逻辑.

3.递归可以进行抽象思维与问题建模能力的训练：

递归迫使程序员将问题分解为自相似子问题，培养“化繁为简”的抽象能力。这种思维是解决动态规划、回溯算法等高级问题的基础
。例如回溯算法中，递归天然支持状态回溯，而递推实现需手动管理状态栈，极易出错。
